# Job Application Bot

A local Playwright-based browser automation project for processing jobs from the job tracker generated by `priya-job-search`.

## Workflow

```text
job-tracker.xlsx
       ↓
Tailored Resume .tex
       ↓
Resume PDF
       ↓
job-application-bot
       ↓
Visible Chromium Browser
       ↓
Application Workflow
```

## Current V1 Scope

The current V1 workflow:

- Reads a job from the tracker
- Resolves the actual hyperlink URL from Excel
- Opens the URL in a visible Chromium browser
- Captures screenshots
- Stops at the current V1 boundary for inspection/human intervention

The bot does not bypass CAPTCHA or OTP.

## Setup

From the repository root:

```bash
cd job-application-bot
```

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it.

macOS/Linux:

```bash
source .venv/bin/activate
```

Windows:

```powershell
.venv\Scripts\activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Install Playwright Chromium:

```bash
playwright install chromium
```

## Input

The bot consumes the job tracker produced by `priya-job-search`.

The tracker should contain the job information required by the application workflow, including:

```text
Title
Company
Location
URL
```

The URL must be an actual Excel hyperlink.

If the cell displays:

```text
Open Job
```

the bot should use the hyperlink target rather than treating `Open Job` as the URL.

## Resume Files

Generate a tailored `.tex` resume from the job's `Resume Prompt`.

Compile the `.tex` file into a PDF and verify that it is one page before using it in the application workflow.

The project contains directories for application inputs and generated artifacts, including:

```text
input/
resumes/
pdfs/
screenshots/
logs/
```

Use the paths expected by the current implementation.

## Run the Bot

From `job-application-bot`:

```bash
python apply_jobs.py
```

The browser is intentionally visible so the workflow can be observed and manually interrupted when necessary.

## Screenshots

Screenshots are stored in:

```text
screenshots/
```

They can be used for:

- Debugging
- Investigating failed flows
- Inspecting unexpected pages
- Human handoff
- Updating selectors after website changes

## Logs

Runtime logs are stored in:

```text
logs/
```

When debugging, inspect both the logs and the corresponding screenshots.

## CAPTCHA and OTP

The bot must not attempt to bypass:

- CAPTCHA
- OTP
- Authentication challenges
- Security verification
- Anti-automation protections

If one appears, stop and complete the verification manually.

## Human Intervention

Human intervention may be required for:

- CAPTCHA
- OTP
- Unexpected verification
- Ambiguous application questions
- Missing required information
- Website layout changes
- Other security-sensitive steps

The goal is to automate repetitive application work while keeping security-sensitive and ambiguous decisions under human control.

## Troubleshooting

### Invalid URL

If Excel displays:

```text
Open Job
```

verify that the cell has an actual hyperlink.

The URL should be obtained from the hyperlink target, for example:

```python
cell.hyperlink.target
```

rather than:

```python
cell.value
```

### Browser does not start

Run:

```bash
playwright install chromium
```

### Website structure changed

Check the latest files in:

```text
screenshots/
logs/
```

Selectors may need to be updated when the target website changes.

### Application stops unexpectedly

Check:

```text
logs/
screenshots/
```

and inspect the visible browser state.

## Current V1 Boundary

The current implementation intentionally stops before fully automating application submission.

The workflow can be extended incrementally:

```text
V1
Open job + inspect
       ↓
V2
Detect application flow
       ↓
V3
Fill safe/repeatable fields
       ↓
V4
Resume upload + application data
       ↓
Human confirmation
       ↓
Submit
```

Security-sensitive and ambiguous steps should continue to require human intervention.
